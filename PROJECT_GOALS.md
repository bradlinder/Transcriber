# Transcriber — Product Vision & Technical Goals

## 1. Product Vision
Transcriber is an offline-first Android application designed for field reporters, journalists, researchers, and content creators. It provides private, high-accuracy, on-device speech-to-text transcription and multi-speaker diarization for `.wav` and `.mp3` audio recordings without relying on cloud APIs or external servers.

---

## 2. Core Functional Requirements

### A. Audio Input & Storage
- Support importing `.wav` and `.mp3` audio files of arbitrary duration (from short 5-second voice memos to 8+ hour interview recordings).
- Resample input audio to $16\text{ kHz}$ mono PCM float arrays (`-1.0f` to `1.0f`) for neural ASR engines.
- Auto-load test audio (`261013_145659_Tr1.WAV`) for instant local testing and verification.

### B. High-Accuracy On-Device Neural Speech Recognition (ASR)
- **Zero Hardcoded Text / Zero Dummy Stubs:** Speech recognition output must be dynamically generated by a real neural ASR model running on device.
- **Word Accuracy Target:** Achieve $\ge 90\%$ Word Accuracy (WER $\le 10\%$) measured against ground-truth reference transcripts.
- **Context Windowing:** Process long recordings in continuous $30\text{-second}$ audio context windows with overlap to preserve full sentence structures and avoid cutting spoken words in half.

### C. Multi-Speaker Diarization
- Identify distinct speakers (`Speaker 1`, `Speaker 2`, `Speaker 3`, etc.) using Voice Activity Detection (VAD) and voiceprint embedding extractors.
- Format transcripts into structured paragraphs with speaker turn badges (`Speaker 1:`) whenever the active speaker changes.

### D. Paragraph Formatting & Timestamps
- Automatically break raw speech token streams into readable paragraphs at sentence boundaries (`.?!`) based on a user-configurable word count threshold (default ~70 words).
- Display time markers (`[MM:SS]`) at the beginning of each paragraph block.

### E. Document Export
- Export completed transcripts to `.docx`, `.txt`, and `.pdf` files in the user's local `Transcripts/` directory.

---

## 3. Architecture & Code Health Standards
- Clean Jetpack Compose UI architecture following Material 3 design system with dark mode themes.
- Comprehensive automated unit and integration tests (`./gradlew testDebugUnitTest`) verifying audio decoding, paragraph formatting, document export, and ground-truth word accuracy benchmarks.
- No network dependencies during transcription execution—100% private, offline, on-device processing.

---

## 4. AI Agent & Development Directives (No Shortcuts Policy)

All AI agents (Gemini, Claude, Copilot, ChatGPT, etc.) assisting on this codebase MUST strictly adhere to these engineering rules:

1. **NO TOP-LAYER HACKS OR STRING HEURISTICS:**
   - NEVER use hardcoded word lists, vocabulary checks, regex heuristics, or string matching to solve audio timing, speaker diarization, or signal processing problems.
   - All signal, timing, and speaker alignment fixes must be grounded strictly in actual acoustic features, neural token timestamps, or energy profiles.

2. **LOW-LEVEL FIRST & PIPELINE INTEGRITY:**
   - Fix issues at their lowest source layer (C++ NDK/JNI, raw PCM audio samples, or neural ASR token output) rather than patching top-level Kotlin wrappers.
   - If low-level data (e.g., word-level timestamps) is required, expose it cleanly from the C++ / JNI engine up to the Kotlin layer.

3. **NO PARAMETER DISTORTION OR ARTIFICIAL CHUNKING:**
   - Do not distort neural model window parameters (e.g., shrinking 3s-6s voiceprint windows down to 2s) to bypass alignment issues, as this destroys voiceprint clustering accuracy on full-length recordings.

4. **THOROUGH PLANNING & PRE-WRITE SANITY CHECK:**
   - Before editing core code, present a 3-bullet technical breakdown confirming:
     1. The exact files and C++ / JNI layers being modified.
     2. The underlying low-level mechanism being used.
     3. An explicit confirmation that zero shortcuts or hardcoded word rules are involved.
